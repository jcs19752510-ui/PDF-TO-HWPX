- 발견된 결함 목록:
  1. **[정합성] 예외 계층 매핑 누락**: 03 §4-2 예외 계층 7종 중 `ContainerBuildError`(HWPX zip 골격 생성 실패, 예: 디스크 공간 부족)가 §0 재확인 목록에는 인지되어 있었으나, 정작 G-4 오류 다이얼로그 표(§2)에는 행 자체가 누락되어 있었다. 03단계가 정의한 예외 클래스 하나가 화면에 전혀 반영되지 않은 것은 "화면에 필요한 상태 누락"에 해당하는 정합성 결함이다.
  2. **[정합성/카피] `OutputPathError`(쓰기 권한 없음) 사용자 문구 미표시**: 03 §4-2는 "출력 디렉터리 쓰기 권한 없음 → `OutputPathError`"까지만 정의하고 실제 사용자 노출 문구는 비워두었는데(다른 엣지케이스는 모두 인용 문구가 있음), 초안은 이 사실을 표에서 암묵적으로 03 원문인 것처럼 다뤄 "04단계가 카피를 보완했다"는 사실이 §2/§7에 드러나지 않았다. 이는 향후 심사자가 "이 문구가 03 산출물인지 04 산출물인지" 추적할 수 없게 만드는 결함이다.
  3. **[표기] 배너 트리거 근거 모호**: G-2의 "대용량 파일 배너"가 `ConversionResult.warnings`(변환 종료 후 값)에서 오는지 `ProgressEvent`(진행 중 값)에서 오는지 초안에서 명확히 구분돼 있지 않아, 03 §4-2 "사전 경고"라는 표현과 어떤 API 필드가 실제로 대응하는지 근거가 흐릿했다.
  4. **[표기] 사전 감지가 신규 API로 오인될 위험**: G-1의 출력 파일 존재 사전 감지 로직이 `overwrite_existing` 외에 별도 조회 API를 요구하는 것처럼 읽힐 수 있는 서술이 있어, "03에 없는 데이터를 화면에 요구했다"는 오판을 유발할 수 있었다.
- 조치 내용: (수정 후 → v1)

  3. §1-1/§2(G-2)/§7에 "`ProgressEvent.message`(loading 단계)"로 명시적으로 못박아, 대용량 배너가 사전 경고(진행 중 표시)이며 종료 후 `ConversionResult.warnings`의 `LARGE_FILE_SLOW` 항목(G-3)과는 별개 레이어임을 §2 G-3 엣지케이스 매핑과 함께 구분.
