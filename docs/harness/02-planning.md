### 0-3. unit-0~4 영향 없음 확인
DEC-020~028은 전부 "배포/인프라/접근방식/보관정책" 층위의 결정이며, 현재 05~06단계에서 진행 중인 unit-0(PDF 로더)·unit-1(텍스트 추출, 재작업 중)·unit-2(이미지 추출, 재작업 중)·unit-3(표 인식, PASS)·unit-4(HWPX 컨테이너, PASS)의 **입력은 여전히 "PDF 바이트"이고 출력은 여전히 "HWPX 바이트"** — 이 프로젝트가 로컬 도구든 웹서버든 이 계약은 동일하다. 따라서 **traceability.md의 unit-0~4 진행 상황(PASS/FAIL/재작업)은 이번 리비전으로 전혀 영향받지 않으며, 오케스트레이터가 §11 제안을 반영할 때도 이 부분은 절대 건드리지 않아야 한다.**

## 1. 서비스/기능 개요 및 목적

**PDF-TO-HWPX**는 (v4까지) 개인이 로컬 PC에서만 쓰는 변환 도구였으나, **DEC-020에 따라 인터넷에 접속 가능한 누구나(익명, 회원가입 불필요) 웹 브라우저로 접속해 PDF 문서를 HWPX(OWPML, KS X 6101)로 즉시 변환할 수 있는 공개 웹 변환 서비스로 전환한다.**

- **목적**: (a) 2026년 진행 중인 정부의 공공문서 HWP→HWPX 전환 정책(01보고서 2-1절)으로 개인이 관공서·학교 제출용 문서를 HWPX로 다뤄야 하는 실질 수요가 생기고 있으나, (b) 기존 경쟁 서비스(01보고서 3절) 중 "설치·가입 없이 즉시 접근 가능"까지 갖춘 경우는 HiPDF(서버 업로드형이지만 무료 사용량 제한) 정도이고, 이 프로젝트는 여기에 "HWPX 네이티브 대응(차별화 포인트 3번)"과 "즉시 삭제로 프라이버시 노출 최소화"를 더해 시장 공백을 메운다.
- **핵심 동작**: 사용자가 브라우저에서 PDF 파일을 업로드하면, 서버가 비동기 작업 큐(REQ-027)에서 이를 파싱해 텍스트/이미지/표 구조를 최대한 보존한 HWPX 파일로 변환하고, 사용자는 짧은 시간 내에 브라우저에서 결과를 다운로드할 수 있다. **업로드 원본과 변환 결과 파일은 모두 TTL 경과 후 서버에서 자동 영구 삭제된다(REQ-028, DEC-022).** 문서 내용을 요약·해석·추천하지 않고 표현 형식만 옮기는 기계적 변환에 한정한다는 v4의 원칙은 그대로 유지한다(01보고서 5-1절 규제 판단의 근거와 동일 선상 — 아래 4절 "규칙 I·J 반영 요약" 참고).
- **비목적(명시적으로 하지 않는 것)**: 문서 내용에 대한 의미적 판단(요약/추천/자동 검토), 실시간 협업/공유 편집 기능(REQ-024), 계정 기반 이력 관리(계정 자체가 없음, DEC-023).
- **v4와의 결정적 차이(정직하게 명시)**: v4의 가치제안 ①은 "PDF 원문이 사용자 PC 밖으로 전혀 나가지 않는다"는 것이었다. **이 약속은 더 이상 유지되지 않는다** — 업로드된 문서는 서버에서 처리·일시 저장된다. 이 트레이드오프를 정직하게 관리하는 방법(즉시삭제, 익명 접근, 개인정보처리방침 고지)은 3절 가치제안과 4절 REQ-026~030에서 다룬다.

## 2. 타깃 사용자 및 페르소나

01보고서 4절에서 도출된 페르소나는 그대로 유효하다(변환이 필요한 "상황"은 배포 형태와 무관). **단, 접근 방식이 "로컬 설치"에서 "웹 접속"으로 바뀌면서 P4의 니즈 충족 수준이 달라진 점만 갱신한다.**

| 페르소나 | 상황 | 근거(01보고서) | v5 갱신 사항 |
|---|---|---|---|
| **P1. 관공서/학교 제출자** | 관공서·학교가 배포한 PDF 서식을 받아, 이를 한글 문서로 채우거나 재편집해서 제출해야 함 | 2-2, 4절 | 없음 — 웹 서비스가 오히려 접근성을 높여 이 페르소나에 더 유리해짐(설치 불필요) |
| **P2. 스캔본 재활용자** | 계약서·오래된 문서 등 스캔된 이미지 PDF를 편집 가능한 한글 문서로 되살려야 함 | 2-2절 | 없음 |
| **P3. 한글 프로그램 미보유자** | 한글 프로그램이 없거나 구버전이라 PDF로 받은 문서를 편집할 수 없음 | 2-2절 | 없음 — 웹 서비스는 이 페르소나가 겪던 "설치 장벽" 자체를 없애 가치제안 ②를 강화 |
| **P4. 프라이버시 민감 사용자** | 계약서·이력서·스캔 신분서류 등 개인정보가 담긴 문서를 외부 서버에 올리고 싶어하지 않음 | 4절 | **(v5 정직한 재평가)** 이 페르소나의 니즈("서버에 안 올림")는 더 이상 100% 충족되지 않는다. 서버가 문서를 일시 처리·저장하는 대신, 즉시삭제(REQ-028)·익명 접근(REQ-026)·처리방침 고지(REQ-030)로 노출을 최소화하는 절충안만 제공한다. **이 페르소나가 여전히 이 서비스를 채택할지는 배포 후 실사용 피드백으로 재검증이 필요하다(§8-3 A-14)** — 정말 100% 로컬 처리가 필요한 사용자는 여전히 알PDF·폴라리스오피스 같은 로컬/브라우저내 처리 대안을 택할 것으로 예상되며, 이 서비스는 그 세그먼트를 포기하는 대신 "접근성"을 택한 것임을 인지해야 한다 |

- **채택하지 않은 후보**: v4와 동일(한컴오피스 고급 사용자 미채택, 근거 불변).

## 6. 제약 조건 (기술/일정/예산/기존 시스템 호환성) — v5 갱신

- **기존 시스템 호환성(v4 유지)**: 프로젝트 자체 소스코드는 unit-0~4만 존재, 신규 프로젝트로 기획. 이 하네스 체계(`ORCHESTRATOR.md`)는 계속 준수.
- **(v5 신규) 외부 프로젝트 구조 참조 제약(DEC-020)**: `AI-AUTO-WORK`(Django 5.2.17+Wagtail 7.4.3, Render+Neon Postgres+Cloudflare R2)의 **config/settings 계층 구조·Render 배포 파이프라인(render.yaml 패턴)·관리자 인증/알림 패턴(Django ADMINS 500에러 알림, `build.sh` 관리자 계정 부트스트랩)을 "가능한 한 전부" 재사용**해야 한다. 단, **Wagtail CMS 앱(blog/comments/subscribers)은 제외한다(DEC-026)** — 이 프로젝트는 콘텐츠 관리가 필요한 블로그가 아니라 파일 변환 도구이므로 Django 프레임워크와 배포 구조만 가져오고, 개인정보처리방침(REQ-030) 등은 일반 Django 템플릿 뷰(정적 페이지)로 구현한다.
- **(v5 신규) 인프라 계정 분리 제약(DEC-027)**: Render 서비스/Neon Postgres 프로젝트/Cloudflare R2 버킷은 AI-AUTO-WORK와 **완전히 별도로 분리된 전용 신규 리소스**를 사용한다. 두 프로젝트의 장애·비용·데이터가 서로 격리된다.
- **기술적 제약(핵심 변환 로직, v4 유지)**: HWPX는 OWPML(KS X 6101) 스펙 준수, 한컴 사양 문서 원문 재배포 금지(01보고서 5-4절). 세로 위치 오차(6-6)·암묵적 검증 규칙(6-8)까지 REQ-008 검증 범위에 포함. 라이브러리 확정은 3단계 권한(DEC-007/008 등 이미 확정된 것은 유지).
- **(v5 갱신) 네트워크/전송 제약**: v4의 "외부 네트워크 호출 없이 동작"이라는 문구는 더 이상 성립하지 않는다(REQ-011 재정의). 대신: **업로드된 사용자 문서를 "PDF→HWPX 변환"이라는 처리 목적 외의 제3자 서비스(특히 클라우드 LLM/OCR API 등)로 전송하지 않는다**는 최소전송 원칙으로 대체한다. 서버가 자사 DB(Neon)·자사 스토리지(R2)에 접근하는 것은 이 제약 위반이 아니다.
- **(v5 신규) 비동기 처리 인프라 제약(DEC-024)**: 구체 기술(Celery+Redis, RQ, Django-Q 등)은 03단계에서 확정. Render 무료 플랜의 단일 워커 제약(AI-AUTO-WORK 선례, decisions.md DEC-024 비고 참고)이 큐 처리량을 제한할 수 있어, 03단계에서 워커 스케일링/큐잉 전략을 재검토해야 한다.
- **(v5 신규) 자원남용 방어 구체 수치**: 파일크기/변환시간/압축해제 상한의 정확한 숫자는 본 문서에서 확정하지 않는다(DEC-025가 3단계 몫으로 위임) — 예시 수준(파일 500MB, 변환 30분)만 참고로 제시.
- **(v5 신규) 예산 제약 변화**: v4는 "완전 무료 개인 프로젝트"(개발 단계 유료 API 미사용)였으나, 이제 서버 호스팅 비용(Render/Neon/R2)이 실제로 발생한다. 무료 플랜 활용을 우선 검토하되, 트래픽 증가 시 실비용 발생 가능성이 있다 — **구체적 예산 상한은 사용자의 가치판단 영역이라 이번 리비전에서 임의로 정하지 않는다(필요시 03단계 착수 전 별도 확인 권고, §8-3 A-16).**
- **법적 제약(v5 갱신)**: 개인정보보호법 실사용 검토 권고(DEC-021) — 개인정보처리방침 게시(REQ-030), 인프라 리전에 따른 국외이전 고지 필요 여부는 03단계에서 실제 리전 확정 후 재확인. 저작권법 제30조(사적이용 복제) 논리는 서버가 처리 주체가 되면서 문자 그대로는 적용되지 않으며, 대신 즉시삭제 정책(REQ-028)으로 저작권법 제35조의2(일시적 복제 면책) 요건 충족을 도모한다(01보고서 5-3절, 확인 필요 항목 그대로 승계).
